How we would work

01

Discovery call

We arrange a call and identify your documentation needs and current system's weaknesses. I begin analysing which tool I think suits your needs best.

02

Audit of existing docs and processes

An inventory of what exists, both what content is missing, and what is wrong with your current publishing process. You'll get a report showing my decision and why, as well as guides to the new processes I propose.

03

Outline my proposal

I write up my proposal in basics, estimate the timescale, and outline my plan. We decide how to move forward.

05

Drafting of documentation structure

Decide the documentation structure and setup the repositories in your existing code storage space.

06

Build CI/CD pipeline

Create the pipeline itself, using the CI/CD tools I've decided on. Create processes for updating and reviewing documentation for future publications

07

Finalise

I hand over your docs site, process, and supporting documentation (e.g. stylguides). I include a guide to the new process I have set out.

08

Optional Maintenance Agreement

Decide if I need to remain available for maintaining of the repositories and pipeline. Agree to a timeline and commitment if so.
